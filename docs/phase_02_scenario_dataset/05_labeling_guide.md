# Ground-Truth Labeling Guide

## Purpose

This guide defines how Phase 2 alerts must be manually labeled.

## Label Values

| Label | Meaning |
|---|---|
| attack_like | Alert was generated by a controlled attack-like scenario |
| benign | Alert was generated by normal admin/user activity |
| noise | Alert is repetitive low-value telemetry |
| false_positive_candidate | Alert looks suspicious but is known benign in this scenario |
| ambiguous | Alert has uncertainty or mixed interpretation |

## Event Role Values

| Event Role | Meaning |
|---|---|
| trigger | Main event that represents the scenario |
| supporting | Related event that supports the scenario |
| duplicate | Repeated version of same signal |
| noise | Low-value unrelated or noisy event |
| unrelated | Not part of the scenario |

## Confidence Values

| Confidence | Meaning |
|---|---|
| high | Directly tied to scenario command and timestamp |
| medium | Likely tied to scenario but field mapping is imperfect |
| low | Unclear relationship or weak evidence |

## Labeling Rules

1. Every labeled alert must have `scenario_id` and `run_id`.
2. Do not label from memory only.
3. Use `scenario_run_log.csv` timestamps.
4. Use evidence screenshots to verify the event.
5. Use `N/A` for MITRE fields when the scenario is benign.
6. Do not inflate MITRE coverage artificially.
7. Preserve uncertainty using the confidence and notes fields.

## Required Label Columns

```text
label_id,alert_uid,scenario_id,run_id,agent_name,timestamp,label,event_role,mitre_tactic,mitre_technique_id,rule_id,rule_description,confidence,ground_truth_summary,notes
```
